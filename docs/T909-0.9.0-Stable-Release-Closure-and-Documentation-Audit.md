## Documentation audit findings and corrections

### Published baseline status

`0.8.0` is now the published stable predecessor. Current-status documents are corrected so they no longer say that 0.8 is awaiting merge/tag/publication or that 0.7 is the current published baseline.

The root README continues to install `0.8.0` until stable `0.9.0` is merged, tagged, and published. T909 does not prematurely advertise the branch package as the current published package.

### 0.9 roadmap status

The 0.9 roadmap is corrected from its initial `T901 active` state to T901–T908 complete / T909 stable-source closure, records the published 0.8 predecessor, the accepted RC head, and the frozen API fingerprint.

### 1.0 roadmap status

The authoritative 1.0 roadmap is corrected from stale 0.8 “merge pending” language. It records 0.8 as published, 0.9 as the stable-source contract freeze after T909 validation, and `1.0.0` as the next release-closure milestone.

### Migration guidance

The migration guide originally retained provisional language saying that T905 might still identify a breaking cleanup. T905 completed without accepting a public breaking change. The guide is corrected to state that 0.8 consumers require no planned source migration to the frozen 0.9 public contract.

### T907/T908 status

The representative-acceptance and RC records are corrected from forward-looking gate wording to accepted/completed status once their exact heads have passed the required matrices.

### Human-readable API baseline

A final `docs/Public-API-Baseline-0.9.md` is added alongside the machine JSON fingerprint. It records the 43 exported types / 309 canonical lines / SHA-256 fingerprint, semantic/lifetime/dependency decisions, nullable/XML contract, and no-breaking-migration result for human review before 1.0.

### Release-page dependency wording

The release workflow had historically embedded a stale `Icod.Terminal 1.0.0` literal in generated GitHub Release notes. During 0.9 development it was corrected to read the `Icod.Terminal` and `Icod.TermInfo` versions from the project `PackageReference` values. T909 verifies the documentation now describes the actual dependency baseline: Terminal 1.4.0 / TermInfo 1.10.0.

### `ncurses` wording

Current prose retains the project convention of writing the library name as `` `ncurses` `` when referenced in documentation. Historical package tags or machine metadata are not rewritten for Markdown presentation.

## Documentation audit result

No documentation review finding requires a runtime or public API change.

The corrections are status, migration-finalization, cross-reference, release-metadata, and compatibility-baseline corrections only. The machine fingerprint and semantic contract remain unchanged from the green RC.

## Stable-source gate

After all T909 package and documentation corrections are committed, one exact stable-source head must pass the complete seven-job T908 matrix.

Only that exact green SHA is the `0.9.0` merge candidate.

After merge, the resulting `main` commit must pass the normal Release validation before `v0.9.0` tagging/publication. Tagging and publication are outside this PR closure and are not performed by T909.
