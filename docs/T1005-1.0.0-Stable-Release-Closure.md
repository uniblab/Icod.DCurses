## Publication-state rule

Stable source is not the same as a published package.

Until merge, post-merge Release validation, `v1.0.0` tagging, publication, and artifact verification complete, consumer installation documentation continues to name the latest actually published package.

## Final stable-source gate

After all T1005 package and documentation changes are committed, one exact branch head must pass the same complete seven-job gate as T1004.

The final SHA is recorded in PR metadata after that matrix closes successfully so documenting the result does not move the tested branch head.

Only that exact green SHA is the `1.0.0` merge candidate.

## Post-merge sequence

After explicit merge of the exact green stable-source head:

1. require the resulting `main` commit to pass the complete `Release` matrix and package validation;
2. tag that validated `main` commit as `v1.0.0`;
3. allow the release workflow to publish NuGet.org and GitHub Packages artifacts;
4. verify `.nupkg`, `.snupkg`, generated SHA-256 checksums, GitHub Release assets, and release-page dependency wording;
5. only then update consumer installation wording to the published `1.0.0` package.

Merge, tag, and publication are outside T1005 branch work.
