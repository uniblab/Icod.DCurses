# Icod.DCurses 0.6.0 — T609 Stable Release Closure

**Release line:** `0.6.0`  
**Current checkpoint:** `0.6.0-rc.1`  
**Assembly version:** `0.6.0.0`  
**Stable predecessor:** `0.5.0`  
**Dependencies:** `Icod.Terminal 1.0.0`; `Icod.TermInfo 1.10.0`  
**Status:** Release closure active

## Purpose

T609 is release closure only. The 0.6 public presentation contract is frozen; no new feature family or public API may enter during this tranche.

The accepted contract is recorded in `docs/Public-API-Baseline-0.6.md` and the detailed T607/T608 acceptance/freeze decisions are recorded in `docs/T607-T608-Presentation-Acceptance-and-Freeze.md`.

## Release-candidate gate

The exact `0.6.0-rc.1` head must pass:

- Windows Staging restore/build/test;
- Linux Staging restore/build/test;
- macOS Staging restore/build/test;
- canonical package validation;
- fresh package-only consumption;
- warning level 4 / warnings-as-errors for both library and tests;
- the frozen public API reflection guard;
- rich rendition lifecycle/disposal acceptance.

No source/API correction should be made after that gate unless the candidate exposes a real defect.

## Stable promotion

After a green RC gate, promotion to stable `0.6.0` changes only release-state metadata:

```text
Version         0.6.0
PackageVersion  0.6.0
AssemblyVersion 0.6.0.0
```

The stable package release notes should describe the already-validated 0.6 contract rather than introduce new work.

## Merge gate

The exact stable-source head must then pass the same PR matrix/package validation. The branch should remain untouched after that result except for PR metadata.

Only that validated stable source head should be merged to `main`.

## Post-merge publication gate

After merge:

1. identify the exact merge commit on `main`;
2. require the full Release x64/ARM64 matrix and Release package validation to pass on that commit;
3. create `v0.6.0` only on that exact green `main` commit;
4. verify NuGet.org and GitHub Packages publication;
5. verify `.nupkg`, `.snupkg`, checksum, and GitHub Release assets.

A tag must never be used to bypass a failing post-merge Release gate.
