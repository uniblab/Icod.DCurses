# Icod.DCurses 2.2 Interaction Public API Design

**Date:** 2026-09-24\
**Status:** T2201 design proposal; discovery contract ready for test-first implementation; sequence contract to be frozen before its implementation\
**Baseline:** published 2.1 public API fingerprint (96 types, 751 lines)

## Decision from application evidence

The editor has a local eight-digit prompt and the roguelike has a local help/movement switch; neither sample currently uses `CursesInteractionRouter`. These are concrete cases for context-sensitive command hints and scoped shortcuts. They do not demonstrate a reusable frame scheduler or timed pointer gesture. Version 2.2 begins with **effective-binding discovery**, then implements bounded multi-key commands against the same precedence. Small prompt input and timing remain explicitly deferred until a second application-shaped witness exists.

Discovery precedes sequences because it exposes the existing precedence without modifying `Route`, provides a concrete parity test, and gives sequence implementation one established effective-binding model. This swaps the initially suggested T2202/T2203 order in the roadmap.

## T2202 — immutable discovery snapshot

Add `public sealed class CursesCommandBinding` with get-only `CursesKeyGesture Gesture` and `CursesCommand Command` properties. Its constructor validates a factory-created gesture and non-null command. A binding describes one **effective single-key** shortcut; it has no handler, label, enabled predicate or retained owner.

Add `public IReadOnlyList<CursesCommandBinding> CursesInteractionRouter.GetEffectiveGestureBindings()`. Each call returns a new, caller-owned, read-only snapshot. It never requires a terminal session or modifies focus except existing lazy eligibility repair. Enumerate focused-region bindings first, then that region's scope ancestors up to and including the active scope, then globals. If no focused region exists, include the active scope's bindings followed by globals. First occurrence of the same gesture wins. Within each owner, sort by semantic key enum value, Unicode scalar (or -1), modifier flags, key phase and function-key number (or -1). This gives deterministic output independent of dictionary enumeration order or registration history. No bindings from above a modal boundary or an ineligible/disposed focused region are visible. The result is empty when none are effective and throws `ObjectDisposedException` after router disposal.

The result contains at most `CursesInteractionRouter.MaximumGestureBindings` (16,384) entries. Snapshot arrays are detached from subsequent bind/unbind, focus or scope changes. No allocation or enumeration work is introduced into ordinary `Route` when discovery is unused. The snapshot is a list of binding identities rather than a command registry; applications own localized names and drawings. On equivalence, use `CursesKeyGesture.Matches` rather than assuming a dictionary key has exactly the same representation as every normalized input; test the Space-key/text representation and key phases.

The T2202 source/package identity becomes `2.2.0-alpha.1` while `AssemblyVersion` stays `2.0.0.0` and the sole direct runtime dependency remains `Icod.Terminal 1.18.0`. Package release notes describe only implemented features, not future sequences.

## T2203 — sequence composition, separate gate

The single-key `Route(CursesInputEvent)` remains unchanged. A new opt-in method will classify normalized key/text events and return pending, completed and fallback results without executing commands. Registration belongs to the existing region/scope/global owners. The T2203 API amendment must first freeze exact names and signatures, sequence length and count ceilings, first-key conflicts, mismatch replay, state invalidation, snapshot representation and text/key equivalence. It must be reviewed and supported by a RED test before production changes. Ordinary `Route` never acquires an implicit wait or timeout.

## Acceptance

Focused, scope-only, nested modal and global bindings must appear in the same order and precedence as `Route`. Hidden bindings must not appear, unbinding must affect future snapshots without mutating prior snapshots, and discovery must not call application code or Terminal. Tests cover disposed owners, unregistered/invalid gesture arguments, capacity bounds and Unicode/modifier/phase identities. Staging PR CI and package-only consumers on .NET 8/9/10 are the verification gate because this workspace has no SDK.
