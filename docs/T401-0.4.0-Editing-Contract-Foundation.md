# T401 — Icod.DCurses 0.4.0 Editing-Contract Foundation

**Project:** `Icod.DCurses`  
**Development line:** `0.4.0`  
**Development version:** `0.4.0-alpha.1`  
**Assembly version:** `0.4.0.0`  
**Stable baseline:** `0.3.0`  
**Dependencies:** `Icod.Terminal 1.0.0`; `Icod.TermInfo 1.10.0`  
**Status:** Foundation established

## 1. Purpose

T401 opens the window editing/composition release line without changing the dependency or terminal-ownership boundary established by earlier releases.

`0.3.0` is the semantic prerequisite for this work: editing operations may rely on its normalized text-element pipeline, Unicode 17 width policy, column-safe helpers, and two-column leader/continuation invariants.

## 2. 0.4 ownership

DCurses owns logical editing operations on the retained virtual screen. Insertion, deletion, copy, overlay, region fill, and drawing therefore transform logical cells only.

Terminal escape-sequence optimization is deliberately not part of this release. A later refresh pass may choose terminal insert/delete/scroll capabilities without changing the logical semantics frozen here.

## 3. Window model

The 0.4 line retains the existing view model:

- windows are projections into one shared `CursesScreen`;
- root-window origins are screen-relative;
- subwindow origins are parent-relative;
- cursor coordinates are window-local;
- overlapping windows share and immediately observe the same logical cells;
- the standard window remains anchored to the complete screen;
- non-standard windows remain lightweight, non-disposable managed views.

No native-style `delwin` ownership contract is introduced.

## 4. Editing invariants

Every 0.4 editing primitive must preserve these rules:

- no operation leaves an orphaned continuation cell;
- a two-column leader is never retained without its continuation;
- an edit boundary may discard a complete wide glyph, but never preserve half of one;
- source/destination overlap is deterministic;
- region-style operations preserve cursor state unless explicitly documented otherwise;
- coordinates and dimensions are validated in window-local space;
- damage/dirty state reflects the logical cells actually changed.
