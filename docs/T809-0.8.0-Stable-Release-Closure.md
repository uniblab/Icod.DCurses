# T809 — Icod.DCurses 0.8.0 Stable Release Closure

**Release:** `0.8.0`  
**Assembly version:** `0.8.0.0`  
**Dependencies:** `Icod.Terminal 1.4.0`; `Icod.TermInfo 1.10.0`  
**Public API delta from 0.7:** none  
**Status:** stable-source merge gate active

## Release decision

T809 is release closure only. The accepted `0.8.0-rc.1` behavioral/public contract is promoted unchanged to stable `0.8.0`.

No new feature family, public API, concurrency primitive, diagnostics type, or dependency enters T809.

## Accepted hardening contract

Stable 0.8 freezes the following production rules:

- logical `CursesScreen`, `CursesWindow`, `CursesPad`, and `CursesPadViewport` mutation is single-writer unless explicitly documented otherwise;
- one Terminal-owned event consumer may wait concurrently with refresh/output activity;
- competing independent event-reader loops remain unsupported;
- terminal-mutating session activity is internally serialized;
- session disposal prevents new terminal activity and unblocks pending DCurses event/lifecycle waits;
- caller cancellation remains distinguishable from disposal-induced wait cancellation;
- canceling one DCurses wait does not discard Terminal decoder state or fragmented input;
- uncertain/partial terminal output invalidates retained physical knowledge for a safe later repaint;
- synchronized-output and other restoration paths preserve independently meaningful dual failures;
- resize/suspend/resume, rich-input handoff, repeated entry/exit, large pads/screens, sparse updates, and no-op refresh behavior are covered by deterministic bounded stress tests.

## Public and dependency freeze

`0.8.0` adds no public API. `docs/Public-API-Baseline-0.8.md` is the release baseline and deliberately retains the public member surface accepted in 0.7.

Package dependencies remain exactly:

- `Icod.Terminal 1.4.0`;
- `Icod.TermInfo 1.10.0`.

Targets remain `net8.0`, `net9.0`, and `net10.0`.

## Pre-merge stable-source gate

Before merge, require the exact stable branch head to pass all six runtime architecture jobs and package validation. Once green, leave that head untouched except for PR metadata.

## Post-merge release gate

Merge, tagging, and publication are intentionally separate later actions. After an explicit merge:

1. require the exact merged `main` commit to pass the Release matrix;
2. verify all Windows/Linux/macOS x64/ARM64 jobs and package validation;
3. only then create/push `v0.8.0` or otherwise trigger the repository's release workflow;
4. verify NuGet.org and GitHub Packages publication, symbols, checksums, and GitHub Release assets;
5. verify the published package declares `Icod.Terminal 1.4.0` and `Icod.TermInfo 1.10.0`.

This branch does not perform the merge, tag, or publication step.
