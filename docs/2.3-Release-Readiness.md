## Dependency policy

Production declares exactly one direct package dependency:
`Icod.Terminal 1.28.0`. Tests and packaging guards verify the direct dependency
identity and reject direct `Icod.TermInfo` coupling. They intentionally do not
duplicate a particular Terminal version: restore, compilation, and the test
suite are the compatibility proof. The tag workflow reads the declared Terminal
version for release notes and requires it to be present.

## Presentation policy

The sample exposes an application-owned ladder:

| Mode | Selection |
|---|---|
| ATLAS | Verified persistent identities and exact geometry |
| FRAME | Explicit ordinary Kitty/Sixel complete-frame output |
| TEXT | Raster unavailable, forced text, or recoverable presentation failure |

Terminal's ordinary raster selection prefers verified Kitty, then verified
Sixel. It does not replay a failed Kitty write through another backend.
`--raster` bypasses persistent negotiation; `--text` forces text.

## Known limits

Acknowledged operations establish ordered completion, not atomic or gapless
physical presentation. Emulator-specific flicker or transient resize artifacts
can remain visible. Historical Kitty 0.32.2 evidence records a missing
animation-upload acknowledgement; no identifier workaround, raw protocol path,
or hidden backend retry is included in DCurses. A current recoverable atlas
presentation timeout causes the sample to abandon the uncertain atlas and use
TEXT.

These limits do not weaken lifecycle safety: ambiguous committed failure still
requires recreation, and DCurses never reuses uncertain persistent identity.

## Maintenance policy

The 2.3 feature roadmap is closed. Subsequent 2.3.x releases are limited to
necessary compatibility, correctness, packaging, and documentation maintenance.
Higher-level widgets belong in a sibling package and do not reopen this release
record.
