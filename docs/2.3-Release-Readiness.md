# Icod.DCurses 2.3 release readiness

Decision date: 2026-10-04. Feature development is **on hold**. Prepare the existing
feature set for release, retain the public contract, and leave the Kitty defect
unresolved. Do not add an identifier workaround, a new backend retry, or further
atlas features. This record supersedes earlier roadmap requests for additional
Kitty diagnosis as a prerequisite to release preparation.

the contract authority.

## What fallback means

Terminal selects **verified ordinary Kitty first, then verified Sixel**. If no
ordinary raster backend is usable, the sample uses TEXT. This selection does not
replay a failed Kitty write through Sixel.

Separately, the default sample attempts persistent ATLAS, then FRAME when atlas
setup is unavailable or recoverably fails and ordinary raster/geometry remain
usable. FRAME can still use Kitty. Recoverable frame failure or atlas presentation
uncertainty selects TEXT. `--raster` bypasses persistent negotiation;
`--text` forces text. Persistent atlas identities are not emulated in Sixel.
DCurses itself does not own a hidden fallback ladder or source-image cache.

Kitty's documented chunked `a=f` final continuation receives no ACK in the
maintainer's standalone test, despite creating the frame. Terminal alpha.5 bounds
the wait; it does not fix the defect. Default startup therefore incurs a bounded
delay before FRAME fallback. Use the existing `--raster` option to exercise
ordinary output directly on this host. No workaround is added.

The [standalone reproducer](../tools/kitty-frame-ack.sh) and
[upstream bug report](../tools/kitty-frame-ack-bug-report.md) preserve the evidence.
Upstream submission was attempted but returned HTTP 403
`Resource not accessible by integration`; **no Kitty issue was created**.
Clean-config and newer-Kitty reproduction remain untested. Animation-control ACK
assumptions are a separate unqualified concern. All these items remain unresolved;
persistent Kitty ATLAS live acceptance is explicitly deferred.
