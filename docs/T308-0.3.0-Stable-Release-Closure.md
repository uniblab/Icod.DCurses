# T308 — Icod.DCurses 0.3.0 Stable Release Closure

**Project:** `Icod.DCurses`  
**Development line:** `0.3.0`  
**Current source version:** `0.3.0`  
**Assembly version:** `0.3.0.0`  
**Dependencies:** `Icod.Terminal 1.0.0`; `Icod.TermInfo 1.10.0`  
**Unicode data baseline:** `17.0.0`  
**Status:** Stable source prepared; final PR validation pending

## 1. Purpose

T308 is release closure only. The feature contract is frozen by T307. No new feature family enters this tranche.

The release candidate proved that the exact public Unicode/terminal-cell contract survives repository tests, packaging, fresh package-only consumption, and the cross-platform Staging matrix. The same frozen source contract is now promoted to stable `0.3.0` for one final PR gate before merge.

## 2. Frozen release contents

The 0.3 release closes with:

- normalized malformed-UTF-16 handling before text-element segmentation;
- complete-text-element width decisions;
- Unicode 17.0.0 generated East Asian Width data;
- Unicode 17.0.0 generated `Emoji` property data for VS16/emoji-ZWJ candidate classification;
- explicit narrow-default / wide-opt-in East Asian Ambiguous policy;
- `CursesText.MeasureColumns(...)`;
- `CursesText.TruncateToColumns(...)`;
- `CursesText.SliceByColumns(...)`;
- screen-owned wide-cell footprint repair across resize and window boundaries;
- Unicode conformance and seeded invariant tests;
- package-only Unicode and column-helper acceptance;
- interactive Unicode diagnostics.

The accepted public delta is frozen in `docs/Public-API-Baseline-0.3.md`.

## 3. Compatibility

The release retains:

```text
Icod.Terminal 1.0.0
Icod.TermInfo 1.10.0
net8.0
net9.0
net10.0
AssemblyVersion 0.3.0.0
```

No new direct package dependency is introduced. The existing Terminal/TermInfo public-type allow-list remains unchanged.

`CursesVirtualScreen` remains exact low-level cell storage when used directly. Stronger footprint guarantees belong to screen-owned structural/window operations rather than redefining that low-level public abstraction.

## 4. Release-candidate gate result

`0.3.0-rc.1` passed:

- Windows Staging build/tests;
- Linux Staging build/tests;
- macOS Staging build/tests;
- canonical package construction and verification;
- symbol-package verification;
- fresh package-only consumers for `net8.0`, `net9.0`, and `net10.0`;
- existing public dependency-boundary tests;
- the frozen 0.3 public API contract tests.

No feature or public-contract change was required after the RC gate.

## 5. Stable source gate

The source is now promoted to:

```text
Version        0.3.0
PackageVersion 0.3.0
AssemblyVersion 0.3.0.0
```

The definitive stable-source PR gate must pass the same Windows/Linux/macOS Staging and package/fresh-consumer validation. Only that green stable source commit should be merged to `main`.

## 6. Post-merge publication gate

After merge, publication remains deliberately separate from PR validation:

1. require the `main` Release matrix to pass on the exact merged commit;
2. create `v0.3.0` only after that commit is green;
3. allow the tag-controlled release workflow to publish;
4. verify NuGet.org and GitHub Packages;
5. verify GitHub Release assets, `.nupkg`, `.snupkg`, and checksums.

The tag must identify the same stable source contract validated in this tranche.

## 7. Completion criterion

`0.3.0` is complete when later window-editing and pad work can rely on one stable definition of Unicode text elements, terminal columns, malformed-input normalization, presentation-width policy, and wide-cell structural boundaries.
