# T208 — 0.2.0 Stable Release Closure

**Project:** `Icod.DCurses`  
**Development line:** `0.2.0`  
**Release version:** `0.2.0`  
**Tranche:** T208 — stable release closure  
**Dependency baseline:** `Icod.Terminal 1.0.0`; `Icod.TermInfo 1.10.0`  
**Status:** Stable source closure prepared; PR validation pending

---

## 1. Purpose

T208 closes the focused `Icod.DCurses 0.2.0` release after the Terminal 1.0
semantic-input parity feature set and the T207 public-API/package regret review.

This tranche is release closure only. It does not add another feature family or
change the accepted `0.2` public input contract.

## 2. Stable package identity

T208 assigns:

```text
Version         0.2.0
PackageVersion  0.2.0
AssemblyVersion 0.2.0.0
```

`Version` and `PackageVersion` remain synchronized. The assembly-version policy
continues to follow the release line.

## 3. Stable dependency graph

The direct runtime dependencies remain exactly:

```text
Icod.DCurses 0.2.0
    -> Icod.Terminal 1.0.0
    -> Icod.TermInfo 1.10.0
```

No new direct package dependency was introduced by the `0.2` feature work.

The public Terminal/TermInfo type allow-list remains unchanged from the `0.1.1`
dependency baseline.

## 4. Stable feature contract

`0.2.0` adds stable curses-owned semantic input support for:

- the complete stable `Icod.Terminal 1.0.0` key vocabulary;
- Super, Hyper, Meta, CapsLock, and NumLock modifier state;
- Press, Repeat, and Release key phases;
- shifted-layout and base-layout character identities;
- associated text reported by modern keyboard protocols;
- F0-F63 through the existing `Function` plus `FunctionKeyNumber` contract;
- optional Disambiguated, EventTypes, and AllKeys keyboard reporting through the
  existing reversible curses input-protocol lease;
- coexistence of keyboard reporting with mouse, focus, and bracketed paste.

Terminal remains the byte decoder, negotiator, response router, and protocol
lifecycle authority.

The accepted `0.2` source contract is recorded in

No T207 API-regret issue required removal or renaming before stable closure.

## 6. Validation contract

Before #13 is merged, the stable `0.2.0` source SHALL pass:

1. Staging restore/build/test on Windows;
2. Staging restore/build/test on Linux;
3. Staging restore/build/test on macOS;
4. structural validation of `Icod.DCurses.0.2.0.nupkg` and `.snupkg`;
5. isolated fresh-package consumer restore/build/execute under `net8.0`,
   `net9.0`, and `net10.0`;
6. the exhaustive production Terminal-to-DCurses semantic mapping tests;
7. the negotiated modern-keyboard/rich-input acceptance test;
8. the public upstream dependency-boundary test;
9. the updated rich-input showcase build across all supported TFMs.

The preceding `0.2.0-rc.1` gate passed all Windows/Linux/macOS runtime jobs and
the canonical package/fresh-consumer job before the stable source version was
assigned.

## 7. Merge and publication gate

T208 deliberately separates source closure from publication.

After the stable source PR is green:

1. merge #13 to `main`;
2. require the six-runner `main` Release matrix to pass on x64/ARM64 Windows,
   Linux, and macOS;
3. create tag `v0.2.0` only from that matching green `main` commit;
4. allow publication only through the tag-controlled release workflow;
5. verify NuGet.org and GitHub Packages publication;
6. verify the GitHub Release `.nupkg`, `.snupkg`, and SHA-256 checksums;
7. verify the package README/banner and symbols from the published artifacts.

The repository README continues to use the known-good `v0.1.1` banner asset
until the `v0.2.0` tag exists; the image content itself is unchanged. A later
post-tag documentation cleanup may repin that URL if desired.

## 8. Completion criterion

`Icod.DCurses 0.2.0` is complete when a fresh consumer can install the stable
package and consume the complete Terminal 1.0 semantic keyboard contract through
DCurses without information loss, accidental mapping exceptions, repository-local
project references, or duplicate terminal-input/protocol ownership.

After stable `0.2.0`, the next feature release is `0.3.0` — Unicode and the
terminal-cell contract.
