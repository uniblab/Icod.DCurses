# T1003 — 1.0 Documentation, Package, and Release Audit

**Release line:** `1.0.0`  
**Candidate:** `1.0.0-rc.1`  
**Purpose:** ensure the frozen 1.0 contract is accurately represented everywhere consumers and maintainers see it

## Documentation review

Before the 1.0 RC can be accepted, review and synchronize current-contract documents:

- root `README.md`;
- `Icod.DCurses-1.0.0-Development-Roadmap.md`;
- `docs/Public-API-Baseline-1.0.md`;
- `docs/Public-API-Fingerprint-1.0.json`;
- `docs/0.9-Contract-Freeze-and-1.0-Migration-Guide.md` as the historical migration bridge into 1.0;
- T1001–T1005 closure records;
- package release notes;
- package/fresh-consumer documentation;
- release workflow wording;
- sample documentation where it states version/dependency/ownership contracts.

Historical 0.1–0.9 milestone records remain historical and are not mass-rewritten to current versions.

## Status/version accuracy

Current documentation must distinguish:

- latest published package/release;
- merged/validated source which may not yet be tagged or published;
- active 1.0 release candidate;
- final stable 1.0 source after T1005.

Do not advertise `dotnet add package ... --version 1.0.0` until 1.0 has actually been merged, tagged, and published.

## API and compatibility wording

Documentation must state that:

- 1.0 promotes the exact 0.9 frozen public contract;
- 1.0 adds no surprise feature family or breaking cleanup;
- the public fingerprint remains 43 exported types / 309 contract lines / SHA-256 `274b87ec28a253e4891f7f72dea847eaf7d57f45e7b6dd2ae4b464e783046639`;
- geometry, Unicode/cell, lifecycle, cancellation, failure, and dependency semantics remain those accepted in 0.9;
- the five approved Terminal/TermInfo public type definitions remain intentional;
- `AssemblyVersion 1.0.0.0` becomes the stable assembly identity.

## Dependency audit

The direct runtime package references must remain exactly:

```text
Icod.Terminal 1.4.0
Icod.TermInfo 1.10.0
```

The package verifier must enforce the generated dependency groups for every target framework.

The GitHub Release workflow must continue deriving displayed dependency versions from the project `PackageReference` metadata rather than hard-coded literals.

## Package audit

Validate the generated `1.0.0-rc.1` package for:

- package id/title/version/author/description;
- LGPL-3.0-or-later metadata and required license acceptance;
- repository/project metadata;
- README/icon/license payloads;
- `net8.0`, `net9.0`, and `net10.0` assemblies;
- matching XML documentation;
- portable symbols and `.snupkg`;
- assembly version `1.0.0.0`;
- exact direct dependency groups;
- fresh package-only consumer build and execution.

## Authors/copyright/license audit

Current consumer-facing documentation must retain the established historical attribution and managed implementation credit, plus:

```text
Copyright (c) 2026 Timothy J. Bruce
```

The library name `ncurses` is written as `` `ncurses` `` in prose Markdown. Machine metadata such as package tags is not altered merely for Markdown styling.

## Workflow/release audit

Confirm:

- PR validation remains `Staging` across Windows/Linux/macOS x64/ARM64 plus package validation;
- `main` validation remains `Release` across the same six runtime architectures plus package validation;
- release tags must point to a commit contained in `main` and match `PackageVersion`;
- tag publication reuses the validated package artifact path and produces NuGet/GitHub Packages, symbols, checksums, and GitHub Release assets;
- no release workflow text contains a stale dependency-version literal.

## Acceptance audit

The 1.0 candidate retains all representative 0.9 acceptance families: editor, pager, Unicode, rich input, lifecycle, ownership, failure recovery, pad/viewport, large-screen, sparse/high-frequency/no-op refresh, and `top`/`slabtop`/`watch` sample builds.

## Gate

T1003 is complete when documentation/package/workflow findings are either corrected or explicitly accepted, with no unresolved mismatch between the actual candidate contract and the consumer/maintainer record.
