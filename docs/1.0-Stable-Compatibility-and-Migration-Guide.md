# Icod.DCurses 1.0 Stable Compatibility and Migration Guide

`Icod.DCurses 1.0.0` is the stable major-version promotion of the public and semantic contract frozen by `0.9.0`.

## Migration from 0.9

There is no planned source migration from the frozen 0.9 contract to stable 1.0.

The stable 1.0 public API fingerprint is intentionally identical to 0.9:

```text
sha256:            274b87ec28a253e4891f7f72dea847eaf7d57f45e7b6dd2ae4b464e783046639
exported types:    43
contract lines:   309
```

The 1.0 release changes package/assembly major-version identity and establishes the stable compatibility commitment. It does not add, remove, or rename public API solely to create a major-version delta.

Exact `1.0.0-rc.1` head `1968bae18610e69e56dc8f720bffb099cb58eb24` passed the complete Windows/Linux/macOS x64/ARM64 plus package/fresh-consumer gate before stable source promotion.

## Assembly identity

`Icod.DCurses 1.0` uses:

```text
AssemblyVersion 1.0.0.0
```

Stable source uses package version `1.0.0` while retaining assembly version `1.0.0.0`.

## Supported targets

The stable package targets:

```text
net8.0
net9.0
net10.0
```

PR and release gates exercise Windows, Linux, and macOS on x64 and ARM64.

## Runtime dependencies

The direct runtime dependencies remain:

```text
Icod.Terminal 1.4.0
Icod.TermInfo 1.10.0
```

DCurses continues to rely on Terminal for live terminal ownership, input decoding, mode/lifecycle handling, and reversible presentation/input-protocol leases. TermInfo remains the terminal-capability authority.

## Public dependency boundary

The only lower-layer type definitions intentionally visible in the stable public API are:

```text
Icod.Terminal.TerminalSession
Icod.Terminal.TerminalEndpoint
Icod.Terminal.TerminalControlResult<T>
Icod.TermInfo.TerminalDescription
Icod.TermInfo.TerminalSize
```

They remain because they represent the authoritative advanced session/endpoint/live-size/terminal-description vocabulary. DCurses does not duplicate these lower-layer concepts merely to hide their namespaces.

## Geometry and text semantics

The stable contract retains:

- zero-based row/column coordinates;
- parent-local subwindow origins;
- rows/columns meaning height/width;
- half-open terminal-column intervals;
- no splitting of two-column Unicode elements;
- Unicode 17.0.0 width data;
- narrow East Asian Ambiguous characters by default;
- `UnicodeCursesTextWidthProvider.WideAmbiguousInstance` for explicit wide-Ambiguous behavior;
- leader/continuation repair when wide-cell footprints are overwritten or clipped;
- semantic line-drawing identity distinct from ordinary Unicode box-drawing text.

## Concurrency and lifetime

The stable 1.x model remains deliberately narrow:

- logical `CursesScreen`, `CursesWindow`, `CursesPad`, and `CursesPadViewport` mutation is single-writer unless explicitly documented otherwise;
- one Terminal-owned event consumer may wait concurrently with refresh/output activity;
- terminal-mutating curses work is serialized internally;
- DCurses does not install a second byte reader or expose a public scheduler/locking abstraction.

## Cancellation and disposal

The stable behavior remains:

- caller cancellation is surfaced as `OperationCanceledException`-compatible cancellation;
- canceling one DCurses wait does not discard Terminal decoder state or fragmented input;
- disposal prevents new terminal work and unblocks pending DCurses event/lifecycle waits;
- disposal-unblocked waits surface `ObjectDisposedException`;
- repeated disposal shares one restoration operation;
- Terminal remains the authoritative owner of host-state restoration.

## Refresh failure and recovery

If output certainty is lost, retained physical-screen knowledge is invalidated conservatively. A later refresh returns through a safe repaint path rather than trusting uncertain terminal state.

When independently meaningful primary and restoration operations both fail, both failures remain observable rather than one being silently discarded.

## Native curses compatibility

Icod.DCurses is a managed curses-style library, not a native ABI wrapper. Native `ncurses` ABI compatibility, exhaustive C curses source compatibility, forms, menus, panels, terminal emulation, PTY ownership, and a widget toolkit remain outside the 1.0 core contract.

## Package publication state

Stable source is not the same as a published package. Consumer installation documentation continues to name the latest actually published version until the `v1.0.0` tag workflow has published and verified the stable artifacts.

## Compatibility evidence

The stable contract is guarded by:

- `docs/Public-API-Fingerprint-1.0.json` and `PublicApiFingerprintTests`;
- a direct 0.9-to-1.0 baseline equality test;
- geometry/Unicode/cell semantic freeze tests;
- lifetime/concurrency/cancellation/failure hardening tests;
- Terminal/TermInfo dependency-boundary tests;
- fresh generated-package consumption;
- editor/pager/Unicode/rich-input/lifecycle/ownership/failure/pad/high-frequency acceptance;
- `top`, `slabtop`, and `watch` acceptance sample builds.
