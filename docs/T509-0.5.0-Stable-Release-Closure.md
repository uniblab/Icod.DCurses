# T509 — Icod.DCurses 0.5.0 Stable Release Closure

**Project:** `Icod.DCurses`  
**Development line:** `0.5.0`  
**Stable source version:** `0.5.0`  
**Assembly version:** `0.5.0.0`  
**Stable published baseline:** `0.4.0`  
**Dependencies:** `Icod.Terminal 1.0.0`; `Icod.TermInfo 1.10.0`  
**Status:** Stable source promoted; final PR validation in progress

## 1. Purpose

T509 is release closure only. The pad/viewport feature and public API contract is frozen by T508. No new feature family enters this tranche.

The release candidate proved that the exact large-surface contract survives repository tests, packaging, fresh package-only consumption, and the cross-platform Staging matrix. The unchanged contract is now promoted to stable `0.5.0` source for one final PR gate.

## 2. Frozen release contents

The 0.5 release closes with:

- dense in-memory `CursesPad` surfaces independent of terminal dimensions;
- normal `CursesWindow` editing through `ContentWindow`;
- destructive rectangular `PresentTo(...)` projection;
- independently pannable `CursesPadViewport` instances;
- absolute and relative pad source positioning;
- shared derived pad views through `CursesWindow.CreateSubwindow(...)`;
- independent `HasVisiblePadChanges` observation per viewport;
- explicit touch/invalidation propagation without a global pad acknowledgement;
- authoritative `Present()` behavior even when the source-change query is false;
- strict destination geometry revalidation after resize/reposition;
- wide-cell-safe source/destination boundary handling;
- very tall/wide pad acceptance and repeated pan/edit workloads;
- package-only execution of the accepted public 0.5 surface;
- opt-in pad-only revision tracking so ordinary logical screens retain their pre-0.5 per-cell memory profile.

The accepted public delta is frozen in `docs/Public-API-Baseline-0.5.md` and guarded by `PublicPadApiContractTests`.

## 3. Intentional exclusions retained at closure

Stable 0.5 does not add:

- pad-owned terminal sessions, modes, input, or physical refresh state;
- a public `CursesSubpad` hierarchy;
- global pad clean/acknowledge semantics;
- resizable viewport geometry;
- automatic destination clipping after resize;
- sparse, virtualized, disk-backed, or memory-mapped pad storage;
- capability-aware semantic drawing policy;
- terminal scrolling/insert/delete optimization.

Those exclusions are architectural decisions rather than incomplete release work.

## 4. Compatibility

The release retains:

```text
Icod.Terminal 1.0.0
Icod.TermInfo 1.10.0
net8.0
net9.0
net10.0
AssemblyVersion 0.5.0.0
Unicode width data 17.0.0
```

No new direct package dependency is introduced. The existing Terminal/TermInfo public-type allow-list remains unchanged.

The stable 0.3 Unicode/terminal-cell and 0.4 window-editing/composition contracts remain authoritative for pad contents and viewport projection.

## 5. Release-candidate result

`0.5.0-rc.1` passed:

- Windows Staging build/tests;
- Linux Staging build/tests;
- macOS Staging build/tests;
- canonical package construction and verification;
- symbol-package verification;
- fresh package-only consumers for `net8.0`, `net9.0`, and `net10.0`;
- existing dependency-boundary tests;
- frozen 0.3/0.4 compatibility tests;
- frozen 0.5 pad/viewport API tests;
- change-tracking opt-in tests;
- large-pad/resize/panning acceptance.

No release-candidate correction was required.

## 6. Stable source promotion

The green RC contract has been promoted unchanged:

1. `<Version>` and `<PackageVersion>` are `0.5.0`;
2. `<AssemblyVersion>` remains `0.5.0.0`;
3. package release notes use stable-release language;
4. repository status and this closure document identify stable source;
5. one definitive stable-source PR matrix and package validation remains;
6. merge is permitted only after that exact stable source head is green.

## 7. Post-merge publication gate

After merge:

1. require the exact merged `main` commit to pass the Release matrix;
2. create `v0.5.0` only after that commit is green;
3. allow the tag-controlled publication workflow to run;
4. verify NuGet.org and GitHub Packages;
5. verify the GitHub Release, `.nupkg`, `.snupkg`, and checksums.

The tag must identify the same stable source contract validated in this tranche.

## 8. Completion criterion

`0.5.0` is complete when the subsequent presentation/rendition work can rely on a stable large-surface and viewport model without redefining pad ownership, panning, shared views, damage observation, or resize semantics.
