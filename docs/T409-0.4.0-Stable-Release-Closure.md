# T409 — Icod.DCurses 0.4.0 Stable Release Closure

**Project:** `Icod.DCurses`  
**Development line:** `0.4.0`  
**Current candidate:** `0.4.0-rc.1`  
**Assembly version:** `0.4.0.0`  
**Stable baseline:** `0.3.0`  
**Dependencies:** `Icod.Terminal 1.0.0`; `Icod.TermInfo 1.10.0`  
**Status:** Release-candidate validation in progress

## 1. Purpose

T409 is release closure only. The feature and public API contract is frozen by T408. No new feature family enters this tranche.

The release candidate must prove that the exact window editing/composition contract survives repository tests, packaging, fresh package-only consumption, and the cross-platform Staging matrix before source is promoted to stable `0.4.0`.

## 2. Frozen release contents

The 0.4 release closes with:

- parent-relative non-standard window repositioning;
- window-local cell inspection;
- validated rectangle fills and clear-to-beginning-of-line;
- Unicode-safe insert/delete cells and lines;
- deterministic destructive rectangle copy;
- blank-transparent rectangle overlay;
- same-window overlapping composition through source snapshotting;
- geometric horizontal and vertical lines;
- six-cell complete-window border drawing;
- range-oriented dirty marking and querying;
- editor-like Unicode editing/composition acceptance;
- package-only execution of the complete public 0.4 surface.

The accepted public delta is frozen in `docs/Public-API-Baseline-0.4.md` and guarded by `PublicWindowEditingApiContractTests`.

## 3. Intentional exclusions retained at closure

Stable 0.4 does not add:

- public `UntouchRegion` dirty-state clearing;
- disposable or independently owned windows;
- a semantic line-glyph enum or border-style type;
- capability-aware Unicode/ACS drawing fallback;
- pads or off-screen large surfaces;
- terminal insert/delete/scroll escape optimization.

Those exclusions are architectural decisions rather than incomplete release work.

## 4. Compatibility

The release retains:

```text
Icod.Terminal 1.0.0
Icod.TermInfo 1.10.0
net8.0
net9.0
net10.0
AssemblyVersion 0.4.0.0
Unicode width data 17.0.0
```

No new direct package dependency is introduced. The existing Terminal/TermInfo public-type allow-list remains unchanged.

The stable 0.3 Unicode/terminal-cell contract remains authoritative for all 0.4 editing and composition operations.

## 5. Release-candidate gate

`0.4.0-rc.1` must pass:

- Windows Staging build/tests;
- Linux Staging build/tests;
- macOS Staging build/tests;
- canonical package construction and verification;
- symbol-package verification;
- fresh package-only consumers for `net8.0`, `net9.0`, and `net10.0`;
- existing dependency-boundary tests;
- frozen 0.3 Unicode API tests;
- frozen 0.4 window-editing API tests;
- editor-like Unicode editing/composition acceptance.

A failure at this stage is fixed without adding feature scope. Any correction that changes the public contract requires explicitly reopening T408.

## 6. Stable source promotion

After a green RC gate:

1. set `<Version>` and `<PackageVersion>` to `0.4.0`;
2. retain `<AssemblyVersion>0.4.0.0</AssemblyVersion>`;
3. update package release notes to stable-release language;
4. update active repository status and this closure document;
5. run one definitive stable-source PR matrix and package validation;
6. merge only the green stable source commit to `main`.

## 7. Post-merge publication gate

After merge:

1. require the exact merged `main` commit to pass the Release matrix;
2. create `v0.4.0` only after that commit is green;
3. allow the tag-controlled publication workflow to run;
4. verify NuGet.org and GitHub Packages;
5. verify the GitHub Release, `.nupkg`, `.snupkg`, and checksums.

The tag must identify the same stable source contract validated in this tranche.

## 8. Completion criterion

`0.4.0` is complete when the subsequent pad/large-surface work can rely on a stable, Unicode-safe window editing and composition contract without redefining geometry, insert/delete, rectangle composition, or damage-range semantics.
