## Purpose

T150 freezes the additive public-contract decisions that T151-T159 implement and records the API-regret review before behavioral implementation expands the 1.4 interaction router.

The release remains a mechanism layer. It does not introduce widgets, a retained event tree, application callbacks, a hidden event loop, automatic focus-on-click, terminal I/O from the router, layout ownership, raster-scene ownership, or backend-selection policy.

## T150 public delta

T150 deliberately adds only candidate numerics and bounds. No new interaction behavior is implemented in this tranche.

The additive numeric contract is frozen as:

```text

```

`Forward` and `Backward` preserve their published 1.4 values and semantics. The spatial values are public candidate vocabulary in T150; behavioral support is implemented and qualified in T153. Until T153, the existing `MoveFocus(...)` implementation continues to reject non-sequential directions rather than silently inventing incomplete behavior.

## Scope ownership and disposal freeze

T150 resolves the remaining scope-disposal question conservatively: **explicit scope disposal does not cascade**.

One router owns one implicit root scope plus at most 256 live explicit scopes. The implicit root is not caller-disposable. Explicit scopes have immutable parentage and a maximum explicit depth of 32 below root.

A region belongs to exactly one scope for its lifetime. A null scope in registration options means the implicit root and preserves 1.4 behavior.

Disposing an explicit scope is legal only when all of these are true:

- the scope has no live regions;
- the scope has no live child scopes;
- the scope is not currently active;
- the scope is not an ancestor of the currently active scope;
- the scope owns no live activation lease.

Otherwise disposal fails atomically with `InvalidOperationException`. Successful scope disposal is one-way and idempotent. There is no implicit subtree destruction and no implicit region disposal.

This keeps ownership explicit and avoids making scope disposal a hidden application-lifetime policy.

## Active-scope freeze

The root scope is active when no explicit activation lease exists.

Explicit activation:

- is represented by a disposable lease;
- is strictly LIFO;
- requires the activated scope to be a descendant of the current active scope;
- forms the modal eligibility boundary for hit testing, focus, capture, and scoped commands;
- saves the previous focus for deterministic restoration when the lease ends;
- performs no callback and no terminal operation.

Out-of-order activation-lease disposal fails deterministically and leaves router state unchanged.

## Pointer-capture freeze

Exactly one capture may be active per router.

Capture is explicit, tied to one owned eligible region and one concrete mouse button, and never implies logical focus. Matching move/release routing may leave the region bounds, so captured targeting uses a separate immutable pointer-target snapshot with signed local coordinates and `IsInside` rather than repurposing `CursesInteractionHit`.

Capture ends on matching release, explicit lease disposal, target invalidation, exclusion by active scope, or router disposal. Stale lease disposal after automatic release is idempotent.

## Spatial-focus freeze

Spatial focus uses effective clipped screen rectangles and integer-only deterministic ranking.

Candidate order is:

1. requested half-plane eligibility;
2. perpendicular-axis overlap before non-overlap;
3. primary-axis edge distance;
4. perpendicular doubled-center distance;
5. ascending existing `TraversalOrder`;
6. ascending registration ordinal.

There is no spatial wrapping. Spatial movement with no current focus returns `null`. Sequential Forward/Backward bootstrap/wrap behavior remains unchanged.

## Pointer-gesture freeze

The 1.5 pointer gesture vocabulary is:

```text
Press
Release
Move
Click
DragStart
DragMove
DragEnd
WheelUp
WheelDown
WheelLeft
WheelRight
```

Classification is clock-free. A click is a same-target press/release with no intervening cell movement. First held-button cell movement produces `DragStart`, later movement produces `DragMove`, and release produces `DragEnd` without an additional click.

Double/triple click, timing thresholds, inertial scrolling, drag/drop payload policy, and hover dwell remain out of scope.

## Scoped-command freeze

Command resolution remains identity-only and callback-free.

With a focused region, precedence is:

```text
focused region
-> focused region scope
-> successive parent scopes through the active-scope boundary
-> router global
-> ordinary targeted result
```

With no focused region, only the active scope's own binding is considered before router-global binding. Inactive outer scope bindings never leak through a modal boundary.

`CursesInteractionResultKind` remains unchanged in T150. Later pointer targeting/gesture data is additive nullable state on `CursesInteractionResult`, not a reason to renumber existing result kinds.

## Test-infrastructure correction

The 1.4 post-merge Release gate observed one Windows ARM64/net10 run where `NoPanelPresenceCheckIsAllocationFree` measured 24 thread-allocation bytes; the unchanged rerun passed. The production path remained exactly:

```text
CursesScreen.HasPanels
-> CursesPanelOrder.Count
-> List<T>.Count
```

T150 keeps the production path unchanged and hardens the measurement by taking eight identical samples and requiring the minimum observed allocation to be zero. This still proves that the steady-state property can execute allocation-free while refusing to mistake one unrelated runtime/JIT/test-harness thread allocation for a product regression.
