# Icod.DCurses 2.0 Approved API Break Manifest

**Baseline:** published `Icod.DCurses 1.6.0`.  
**Baseline fingerprint:** 75 exported types; 559 canonical declared contract lines; SHA-256 `266e23e6f3b4d5be98c81b5d5774f1de47d488d9ede7025877e46388cae6d458`.  
**Status:** frozen T2001 break set; implementation begins in T2002 only after the Terminal readiness gate permits it.

## Approved declared-contract changes

The fully qualified signatures below are the complete approved source break set. Formatting is C#-equivalent to the canonical reflection contract; nullability and generic arguments are explicit.

| Action | 1.6 signature | 2.0 signature |
|---|---|---|
| Remove/replace property | `public Icod.TermInfo.TerminalDescription Icod.DCurses.CursesSession.Terminal { get; }` | `public Icod.Terminal.TerminalProfile Icod.DCurses.CursesSession.Profile { get; }` |
| Change return type | `public Icod.Terminal.TerminalControlResult<Icod.TermInfo.TerminalSize> Icod.DCurses.CursesSession.GetDimensions()` | `public Icod.Terminal.TerminalControlResult<Icod.Terminal.TerminalDimensions> Icod.DCurses.CursesSession.GetDimensions()` |
| Change return type | `public Icod.Terminal.TerminalControlResult<Icod.TermInfo.TerminalSize> Icod.DCurses.CursesSession.SynchronizeDimensions()` | `public Icod.Terminal.TerminalControlResult<Icod.Terminal.TerminalDimensions> Icod.DCurses.CursesSession.SynchronizeDimensions()` |
| Change property type | `public Icod.TermInfo.TerminalSize? Icod.DCurses.CursesLifecycleEvent.Dimensions { get; }` | `public Icod.Terminal.TerminalDimensions? Icod.DCurses.CursesLifecycleEvent.Dimensions { get; }` |

The `Profile` addition replaces the removed low-level description escape hatch; it is not an additional fifth migration family. The two dimensions methods keep their names and controlled-result vocabulary. The lifecycle property keeps its name and nullable availability meaning.

## Assembly identity break

| 1.6 | 2.0 |
|---|---|
| `AssemblyVersion 1.0.0.0` | `AssemblyVersion 2.0.0.0` |

T2002 establishes `Version` and `PackageVersion` as `2.0.0-alpha.1` together and changes `AssemblyVersion` to `2.0.0.0`. Consumers must rebuild against 2.0; no binding-compatible claim is made across this major boundary.

## Preserved public contracts

The following are explicitly outside the approved break set and remain source-shaped unless a later roadmap amendment is reviewed:

- `CursesSession.OpenAsync(TerminalSession, ...)` and Terminal session ownership transfer/failure behavior;
- `CursesSession.InputEndpoint`, `OutputEndpoint`, `IsInteractive`, `Options`, `Screen`, `StandardScreen`, lifecycle APIs and input APIs;
- `TerminalControlResult<T>` status, value, message and native-error semantics;
- public Terminal endpoint and `TerminalRasterImage` usage already accepted in 1.6;
- `CursesPresentationCapabilities` public type and members, reimplemented as an explicit projection from `TerminalProfile.Screen`;
- all DCurses geometry, cells, styles, metadata, Unicode width, windows, pads, panels, interaction and retained-raster facade types;
- method names, parameter order/defaults, nullability, enum numeric values, generic constraints and declared exceptions not named in the approved table.

Changing implementation ownership from TermInfo/raw output to Terminal plans and transactions is not permission to change these public contracts or visible retained-screen semantics.

## Deliberately unsupported compatibility mechanisms

DCurses 2.0 does not provide:

- an obsolete `CursesSession.Terminal` shim returning `TerminalDescription`;
- a DCurses type-forwarder for `TerminalDescription` or `TerminalSize`;
- duplicate DCurses profile/dimensions models;
- implicit conversion between `TerminalSize` and `TerminalDimensions`; or
- a second overload whose only purpose is to preserve a TermInfo-bearing signature.

Applications that require the 1.x public surface remain on DCurses 1.6.x. Advanced TermInfo description construction remains a Terminal/session-configuration concern outside DCurses.

## Review and machine-gate policy

T2002 must generate a new 2.0 fingerprint instead of overwriting a 1.x artifact. Its API review must compare the compiled 2.0 contract against the frozen 1.6 contract and this manifest:

1. every removed or changed 1.6 canonical line maps to one row above;
2. the new `Profile` property is present with the exact Terminal type;
3. no public TermInfo type remains recursively in return types, parameters, generic arguments, fields, properties, events, constructors, constraints, attributes, base types or implemented interfaces;
4. all unrelated 1.6 declared contract lines remain present; and
5. the assembly version is exactly `2.0.0.0` when T2002 changes development identity.

Any additional removal, rename, signature change, nullability change, enum change or new breaking behavior requires an explicit rationale, an amendment to the 2.0 roadmap and this manifest, and review before implementation.
