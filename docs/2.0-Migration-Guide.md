# Migrating Icod.DCurses 1.6 to 2.0

**Status:** guide for the unpublished `2.0.0` stable-source candidate. Published `Icod.DCurses 1.6.0` keeps its own API and direct package dependencies. The 2.0 public break is frozen in [the API break manifest](2.0-API-Break-Manifest.md); the direct dependency removal was [qualified in T2007](T2007-TermInfo-Dependency-Removal-Gate.md).

## Package and rebuild

DCurses 2.0 targets `net8.0`, `net9.0`, and `net10.0`, directly requiring `Icod.Terminal 1.18.0` and no direct `Icod.TermInfo` package. NuGet can still restore TermInfo through Terminal. Existing consumers must rebuild: the DCurses assembly version changes from `1.0.0.0` to `2.0.0.0`, and the profile/dimensions signatures change at source level. Do not add a direct TermInfo reference merely to use DCurses 2.0. The alpha candidate is not published; the PR package validation uses an isolated local package source and a project declaring only `Icod.DCurses`.

## Public API changes

The following examples show each approved breaking family. Add `using Icod.Terminal;` for the new Terminal types. Code using other DCurses retained presentation and interaction types is source-shaped as before.

| 1.6 | 2.0 |
| --- | --- |
| `Icod.TermInfo.TerminalDescription description = session.Terminal;` | `TerminalProfile profile = session.Profile;` |
| `TerminalControlResult<Icod.TermInfo.TerminalSize> size = session.GetDimensions();` | `TerminalControlResult<TerminalDimensions> size = session.GetDimensions();` |
| `TerminalControlResult<Icod.TermInfo.TerminalSize> size = session.SynchronizeDimensions();` | `TerminalControlResult<TerminalDimensions> size = session.SynchronizeDimensions();` |
| `Icod.TermInfo.TerminalSize? size = lifecycle.Dimensions;` | `TerminalDimensions? size = lifecycle.Dimensions;` |

For example, read the session's semantic profile and live dimensions without relying on a TermInfo description:

```csharp
using Icod.DCurses;
using Icod.Terminal;

await using CursesSession session = await CursesSession.OpenAsync();
TerminalProfile profile = session.Profile;
TerminalControlResult<TerminalDimensions> observed = session.GetDimensions();
CursesWindow screen = session.StandardScreen;

if ( observed.IsAvailable ) {
	TerminalDimensions dimensions = observed.GetRequiredValue();
	screen.Move( 0, 0 );
	screen.Write( $"{profile.Name}: {dimensions.Columns}x{dimensions.Rows}" );
	await session.RefreshAsync();
}
```

The [minimal sample](../samples/Icod.DCurses.Sample/Program.cs) also shows an unavailable-size path. The result of `GetDimensions()` can be unavailable, unsupported, or failed; preserve its status/message/native error rather than inventing a size. `SynchronizeDimensions()` applies a successful live observation to DCurses and invalidates physical presentation. For resize and resume events, `CursesLifecycleEvent.Dimensions` is nullable; absent dimensions remain absent. Recompute application layout from the updated `session.Screen.Bounds` when a repaint is required.

## Output and recovery

Continue changing retained `CursesWindow`, `CursesPad`, `CursesPanel`, hyperlink, and raster content through the public DCurses APIs, then call `CursesSession.RefreshAsync()`. DCurses prepares one semantic screen transaction; Terminal owns its command encoding, serialized output, synchronization, required cleanup, and flush. Application code should not send capability strings, write through a borrowed output stream, or separately flush for the same presentation. The exact Terminal profile and screen capabilities come from `session.Profile` / `session.PresentationCapabilities`.

Terminal bounds one transaction at 65,536 retained items and 64 MiB of UTF-8 application payload. DCurses does not split an oversized refresh into raw writes. A cancelled attempt before commitment emits nothing; once commitment starts, Terminal completes required trailing output and cleanup despite later caller cancellation. If a write, flush, or lifecycle operation fails, keep the original failure visible, repair the cause, call `session.Invalidate()` if a complete repaint is needed, and explicitly retry `RefreshAsync()`. Do not assume that physical state was published merely because some bytes reached the terminal. A stale or released raster placeholder must be replaced with a caller-provided current resource; DCurses will not silently recreate it from source pixels.

Terminal-specific session construction or profile selection belongs in `Icod.Terminal`. For advanced configuration, open a `TerminalSession` first and pass it to `CursesSession.OpenAsync(terminalSession, options)`. On successful initialization, disposing DCurses also disposes the supplied Terminal session; if initialization fails before ownership transfer, the caller still owns it. DCurses 2.0 has no compatibility property exposing `TerminalDescription`, no TermInfo type forwarder, and no second capability database. Keep 1.6.x for applications that require the old public surface until they can migrate.

## Consumer coverage

The [sample index](../samples/README.md) covers retained plain/styled text, line drawing, hyperlinks, pad/viewport composition, panels, interaction, and optional raster ownership. The [package-only smoke consumer](../tools/package-smoke/Program.cs) restores the built package in isolation for all three target frameworks, checks the profile/dimensions contract and retained public surface, and has an optional interactive path for a live Terminal session. The optional raster path may report unavailable on a terminal without that feature; retain ordinary text and metadata in that case.
