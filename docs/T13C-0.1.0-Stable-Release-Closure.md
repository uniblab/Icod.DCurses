## 1. Purpose

T13C closes the first stable `Icod.DCurses` release after the public-API regret
pass and the published Icod.Terminal 0.3 downstream-acceptance checkpoint.

This tranche is intentionally release-focused. It does not add a new DCurses
feature family or change the accepted 0.1 public contract.

## 2. Stable dependency freeze

The stable direct runtime dependencies for `Icod.DCurses 0.1.0` were:

```text
Icod.Terminal 0.3.0
Icod.TermInfo 1.4.1
```

Alpha-22 validated the Terminal 0.3 architecture using the published
`Icod.Terminal 0.3.0-alpha.8` / `Icod.TermInfo 1.3.0` checkpoint. T13C advanced
the package to the subsequently published stable dependency versions without
reintroducing a private terminal reader, parser, response router, or terminal
capability database in DCurses.

`Icod.DCurses 0.1.1` later advanced this same accepted ownership contract to
`Icod.Terminal 1.0.0` and `Icod.TermInfo 1.10.0`.

## 6. Stable validation gate

The T13C release gate required:

1. Debug, Staging, and Release solution builds to remain clean for `net8.0`,
   `net9.0`, and `net10.0`.
2. The ordinary test suite to pass under all three target frameworks.
3. All six sample projects to build under all three target frameworks as part of
   the solution.
4. The stable package to pack all three target-framework payloads successfully.
5. Structural package verification to pass for all three framework payloads,
   dependency groups, XML documentation files, and portable PDBs.
6. The isolated package-only consumer to restore, compile, and execute under
   `net8.0`, `net9.0`, and `net10.0` using the stable dependency graph.
7. The PR Release/package-only matrix to pass on Windows, Ubuntu, and macOS.
8. `git diff --check` to report no whitespace errors.

After merge, the `main` validation matrix and tag-controlled publication path
completed the stable release process.

## 7. Completion criterion

T13C completed when a fresh consumer could install `Icod.DCurses 0.1.0`, restore
its stable runtime dependencies without repository-local project references,
build against the public API, and the tag-controlled release workflow could
publish the validated package successfully.
